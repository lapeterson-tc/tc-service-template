# Build and package

## The canonical sequence

Order matters. `tcex package` zips whatever is on disk — it does not build
anything — so the UI must already be compiled and the Python dependencies
already vendored before you run it.

```sh
cd ui
npm install
npx ng build          # -> ../ui_build/browser/
cd ..
tcex deps             # -> deps/   (vendored Python packages)
tcex package          # -> target/<app_name>_v1.tcx
```

For a fully clean UI rebuild (after an Angular or dependency change):

```sh
cd ui && rm -rf node_modules package-lock.json .angular && npm install && npx ng build && cd ..
```

## Where things go, and why

| Path | Produced by | Ships in the `.tcx`? |
|---|---|---|
| `ui/` (Angular source) | you | **No** — excluded in `tcex.json` |
| `ui_build/browser/` | `ng build` | **Yes** — this is the UI that runs |
| `deps/` | `tcex deps` | **Yes** — this is the Python import path |
| `.venv/` | you, for tests only | No |
| `target/*.tcx` | `tcex package` | — it *is* the package |

**`ng build` writes to `../ui_build`, not `ui/dist`.** `angular.json` sets
`outputPath.base` to `../ui_build`, and Angular 17+'s application builder puts
browser artifacts in a `browser/` subdirectory of that base. The server serves
exactly `ui_build/browser` (`core/api/falcon_app.py:ui_files`) and the app
**hard-exits at boot** if it is missing.

**The `ui/` source is excluded from the package, so only the build output
ships.** Forget to rebuild before packaging and you silently ship a stale UI
with fresh backend code — a mismatch that produces confusing 404s rather than
an obvious error. Rebuild the UI as a reflex before every package.

**There is no runtime virtualenv.** `run.py` inserts `deps/` at the front of
`sys.path` before importing anything third-party, and exits with a clear
message if `deps/` is absent. `.venv/` exists only so `pytest` can run
locally.

## Pinning: the pydantic trap

`tcex` pins **pydantic 1.x**. Any dependency that has moved to pydantic v2
must be held on its last v1-compatible major, or the app dies at import with:

```
ImportError: cannot import name 'RootModel' from 'pydantic'
```

`requirements.txt` therefore pins `spectree[offline]>=1.5.8,<2`. Apply the
same caution to anything new you add that touches pydantic.

`requirements.lock` is generated by `tcex deps` and **is used in preference to
`requirements.txt` on subsequent runs**. After editing `requirements.txt`,
delete the lock (and `deps/`) so the change actually takes effect:

```sh
rm -rf deps requirements.lock && tcex deps
```

## Tests and lint

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest

cd ui && npx ng lint && npx ng test --watch=false --browsers=ChromeHeadless
```

`conftest.py` mirrors `run.py`: it puts the repo root and `deps/` on
`sys.path`. Pure-logic tests run on a fresh checkout with no `deps/`;
endpoint tests skip themselves via `pytest.importorskip`. Both states should
be green — check occasionally with `mv deps deps.bak && pytest; mv deps.bak deps`.

There is no Python linter configured. `ng lint` covers the UI and must stay
clean; `npx ng lint --fix` handles the prettier formatting rules.

## Versioning

`programVersion` appears in **`install.json`** and **`app_spec.yml`**, and the
UI shows it in the header (it reads the value from `install.json` at runtime
via `/api/tc/app-config`). Keep them in sync, and add a matching entry to
`app_spec.yml`'s `releaseNotes` and to `README.md`.

`app_spec.yml` is the source of truth; `tcex spec` regenerates `install.json`
from it.

## Verifying the package

Nothing checks the exclusions for you, so look inside before shipping:

```sh
python3 - <<'PY'
import zipfile, collections
z = zipfile.ZipFile('target/TC_Service_Template_v1.tcx')
names = z.namelist(); root = names[0].split('/')[0]
tops = collections.Counter(n[len(root)+1:].split('/')[0] for n in names if len(n) > len(root)+1)
for k, v in sorted(tops.items()):
    print(f'{k:24} {v}')
PY
```

You want `install.json`, `run.py`, `app.py`, `api`, `core`, `deps`,
`ui_build`. You do **not** want `ui`, `tests`, `docs`, `scripts`,
`app_spec.yml`, `conftest.py`, `pytest.ini`, or `requirements-dev.txt` — those
are excluded in `tcex.json` and their presence means an exclusion drifted out
of sync with a renamed file.
